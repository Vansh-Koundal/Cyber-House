# CyberHouse

A home-network safety checker for people who are not technical. It finds the devices on your Wi-Fi,
works out what each one is, flags risky open services, explains each problem in plain English and shows
a Home Safety Score that climbs as you fix things.

**Live demo:** https://cyber-house.streamlit.app

## How it works (and why there are two parts)

A website cannot see inside your home Wi-Fi: it runs in a data center, and browsers do not allow
websites to scan local networks. So CyberHouse has two parts:

1. **The scanner** (`CyberHouse-Scanner.exe`, built from `agent.py`) runs on a computer at home. It needs no
   admin rights and no extra drivers. It only looks, it never changes anything, and it saves `cyberhouse_scan.json`.
2. **The website** (`app.py`, Streamlit) reads that file and shows the dashboard, the fix plan and a PDF report.

### Use it
1. Open the website and press **Download the scanner** (or get it from the Releases page).
2. Double-click it, type `YES`, wait 1-2 minutes. Windows may say "Windows protected your PC" because the
   file is not code-signed yet: click **More info -> Run anyway**.
3. Upload the `cyberhouse_scan.json` it saved to your Desktop. Tick the permission box and press **Show results**.

Or just pick a sample home in the sidebar to explore the dashboard.

## The AI, honestly
- **Device recognition:** TF-IDF on the device's brand/name text plus its open-port signature, into a logistic
  regression. It is trained on synthetic device profiles, so its held-out accuracy on that synthetic data says
  little about real homes. Run `python eval_real.py` on devices you have labelled yourself for a real number.
  Result on one real home: **[fill in: X of Y correct]**.
- When the model is not sure it says so, and (in the local version) you can correct it and it learns from your fix.
- **Scoring:** the risk database (`risk_db.json`) sets points per risky service, weighted up for devices that see or
  hear inside the home (cameras, baby monitors, speakers, storage). An open port is a risk indicator, not proof of
  a vulnerability. We do not test passwords or exploit anything.
- The plain-English explanations are written from templates, not generated by an LLM.

## Run it yourself
```
pip install -r requirements.txt
streamlit run app.py            # dashboard; Demo mode on by default
python agent.py                 # the scanner (pip install -r requirements-agent.txt first)
pytest                          # tests (pip install pytest)
```
Set `HOSTED_DEMO=1` (environment variable or Streamlit secret) for the public-website mode: no scanning on the
server, upload-a-scan-file instead, and no shared "teach the AI" file.

## Build the scanner .exe
Push a tag and GitHub builds it: `git tag v1.0 && git push origin v1.0`. The file appears under Releases.
By hand: `pip install -r requirements-agent.txt pyinstaller` then
`pyinstaller agent.py --onefile --name CyberHouse-Scanner --collect-all manuf`.

## Project layout
| File | What it does |
|---|---|
| `app.py` | Streamlit dashboard |
| `agent.py` | The scanner people run at home |
| `scanner.py` | Device discovery (no admin needed), port scan, banner grab, UPnP / certificate / Wi-Fi checks |
| `scan_io.py` | Scan-file format, with validation of uploaded files |
| `aiml_engine.py` | Device classifier and plain-English explainer |
| `evaluator.py` | Risk scoring |
| `pdf_generator.py` | PDF report |
| `risk_db.json` | Risk database |

## Limits
- It sees the network the computer is connected to. Guest Wi-Fi or "AP isolation" can hide devices.
- Sleeping devices may not show up; scan again if one is missing.
- The Wi-Fi security check only works on English-language Windows.
- Small test sample for the AI so far; treat device guesses as hints.

## Privacy and ethics
The scan file contains device names and hardware addresses. The website reads it for your session only and does
not save it. Only scan networks you own or have permission to test.
